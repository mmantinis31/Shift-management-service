# Shift Management Service

A REST API for registering employee shifts. It validates scheduling rules, prevents overlapping shifts, checks Lithuanian public holidays and optionally records a notification with each shift.

## Requirements and stack

Docker with Compose v2 is required. PHP and Composer run inside the containers.

- PHP 8.4, Symfony 7.4 LTS and Composer
- Nginx and PHP-FPM
- SQLite, Doctrine ORM 3 with XML mapping and Doctrine Migrations
- Symfony HttpClient, Serializer, Validator and Cache
- PHPUnit 13, PHPStan, PHP_CodeSniffer and PHP CS Fixer

Dependency versions are locked in `composer.lock`.

## Setup

From the project root:

```bash
docker compose build
docker compose run --rm --no-deps php composer install --no-interaction
docker compose run --rm --no-deps php php bin/console doctrine:migrations:migrate --no-interaction
docker compose up -d --wait
```

The API is available at `http://localhost:8080`. To check HTTP availability:

```bash
curl --fail http://localhost:8080/health
# {"status":"ok"}
```

If port 8080 is occupied, start with `HTTP_PORT=8081 docker compose up -d --wait`.

SQLite data is stored in `var/data/shifts.sqlite` on the host and survives container recreation, including `docker compose down -v`. Dependencies and runtime caches use separate named volumes. Database files, caches and local environment overrides are ignored by Git.

The database directory must be writable by the container user. On Linux, if necessary, run this before the migration command:

```bash
docker compose run --rm --no-deps --user root php chown www-data:www-data /app/var/data
```

After dependency changes, rerun `composer install` through the container. Rebuild the image after Dockerfile or PHP configuration changes. Use migrations for schema changes.

The tracked `.env` contains local defaults. Copy `.env.example` to `.env.local` to override Symfony settings. Compose reads `HTTP_PORT` from `.env` or the shell; it does not read `.env.local`.

## API

### Create a shift

```bash
curl -i http://localhost:8080/shifts \
  -H 'Content-Type: application/json' \
  -d '{
    "employee_id": "employee-123",
    "date": "2026-10-06",
    "start_time": "09:00",
    "end_time": "17:00",
    "country_code": "LT"
  }'
```

Response: `201 Created`.

```json
{
  "id": "d5a70184ab8c4d84a078dd24772b3ff46",
  "employee_id": "employee-123",
  "date": "2026-10-06",
  "start_time": "09:00",
  "end_time": "17:00",
  "country_code": "LT"
}
```

All five request fields are required strings; unknown fields are rejected. Employee IDs must be nonblank and at most 255 characters. They are preserved exactly, including case and trailing spaces.

Dates must be valid calendar dates in `YYYY-MM-DD` format; times must use the 24-hour `HH:mm` format. Shifts must end later on the same day and last no more than 12 hours. Shifts for the same employee and date cannot overlap; adjacent shifts are allowed. Only `LT` is supported. Dates and times are local values, without timezone or daylight-saving conversion.

### Errors

```json
{
  "error": {
    "code": "overlapping_shift",
    "message": "The employee already has an overlapping shift on this date.",
    "details": []
  }
}
```

| Status | Meaning |
| --- | --- |
| `400` | Malformed JSON or invalid request fields, types, formats or country |
| `409` | Overlapping shift |
| `415` | Unsupported content type; use `application/json` |
| `422` | Invalid shift duration/order or public holiday |
| `503` | Holiday verification unavailable or SQLite lock timeout |
| `500` | Unexpected internal failure |

Validation errors include field names and messages in `details`. Internal exception details are logged and excluded from API responses. `503` responses include `Retry-After: 5`. Errors generated by Nginx before a request reaches PHP use Nginx's response format.

## Architecture and persistence

The application uses a small ports-and-adapters structure:

| Layer | Responsibility |
| --- | --- |
| `Domain` | Immutable `Shift` entity, `ShiftPeriod` value object, business invariants and repository contract |
| `Application` | `CreateShiftHandler` and contracts for holidays, notifications and transactions |
| `Adapter` | Doctrine persistence, Nager HTTP integration, caching and notification recording |
| `UI/Http` | Controllers, validated request/response DTOs and JSON error handling |

Domain classes have no Symfony or Doctrine dependencies. XML mapping in `Adapter/Persistence/Mapping` embeds `ShiftPeriod` in the shift row. Doctrine provides persistence and migrations while keeping mapping outside Domain; SQLite avoids a separate database server.

The controller maps a validated DTO to an application command. The handler verifies holidays, then checks overlap, saves and notifies inside one transaction. Domain validation also protects callers outside HTTP. An employee/date/start-time index supports overlap lookups.

### Transaction policy

PDO SQLite connections enable foreign keys, WAL mode and a busy timeout. The middleware uses `BEGIN IMMEDIATE` for **all outer DBAL transactions**, including migrations and read-only transactions. Writer reservation precedes the overlap query. Nested transactions remain DBAL-managed savepoints; other drivers are unchanged.

SQLite serializes writers across the database; WAL permits concurrent readers. Holiday HTTP calls run before the transaction and hold no database lock.

Shift and notification writes commit together. Failures trigger rollback and clear managed entities; a failed rollback or uncertain commit state causes the connection to be discarded. Lock timeouts return `503`. Transactions are not automatically retried.

### Holidays and notifications

The Nager adapter requests `Holidays/LT/{year}` with a 3-second inactivity timeout, a 5-second total limit and no redirects. A holiday blocks a shift only when `nationalHoliday === true` and `holidayTypes` contains `Public`.

Response structure and required fields are validated before caching results by country/year. Invalid records are rejected without caching. Rejecting an empty annual list for Lithuania is an additional conservative assumption. Valid cache entries remain usable until expiry; without valid data, failed verification returns `503`.

`SHIFT_NOTIFICATIONS_ENABLED` selects `DatabaseShiftNotifier` or `NullShiftNotifier` through DI. Enabled notifications store employee/date/time in a separate table on the same connection; the null adapter performs no writes.

## Tests and quality checks

With the PHP container running:

```bash
docker compose exec php composer verify
```

This validates Composer, DI, YAML and ORM mapping, then runs PHPCS, Symfony formatting rules, PHPStan at maximum level without a baseline, and PHPUnit.

```bash
docker compose exec php composer test:unit
docker compose exec php composer test:integration
docker compose exec php composer test:functional
docker compose exec php composer style:fix
```

Unit, integration and functional tests cover business rules, HTTP validation, external failures, notification atomicity and independent-process concurrency. Holiday calls use fakes or mocked HTTP responses. Tests use `var/test/shifts_test.sqlite`; its reset helper guards the environment, driver and path. Do not run suites concurrently against that file.

To run the full quality gate with separate volumes on a network without external access:

```bash
docker compose -p shift-management-check -f compose.yaml -f compose.test.yaml build php
docker compose -p shift-management-check -f compose.yaml -f compose.test.yaml run --rm --no-deps php composer verify
docker compose -p shift-management-check -f compose.yaml -f compose.test.yaml down -v
```

Image builds require internet access; tests do not. ORM schema synchronization is skipped because notifications are DBAL-managed; an integration test checks the mapped shift table against the migration schema.

## Limitations and production considerations

SQLite serializes writes, and the holiday cache is local to one instance. Requests have no idempotency key: if creation commits but the response is lost, repeating the request returns `409`. For a larger deployment, I would revisit database concurrency, introduce idempotency keys, and add monitoring and tested backup/recovery procedures. Holiday cache freshness and outage handling would depend on operational requirements.
